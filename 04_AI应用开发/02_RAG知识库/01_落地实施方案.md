# personal-test-rag 落地实施方案

> [!info] 本文档定位
> [[00_个人知识库RAG项目进度]] 负责记录"做什么和为什么"；本文档负责"具体怎么做"——所有选型已定死，照着做即可。规划文档中"十四、问题与待确认项"在本文档第一节全部给出结论。

## 一、选型决策（直接采用，不再讨论）

| 待确认项 | 决策 | 理由 |
| --- | --- | --- |
| Embedding 模型 | 本地 `BAAI/bge-m3`（sentence-transformers），向量维度 **1024** | 笔记是私有资料，本地生成向量零外泄；中文效果好；约 700 个切片在 Mac 上几分钟跑完，不需要 API |
| Embedding 降级方案 | `BAAI/bge-small-zh-v1.5`（512 维） | 如果 bge-m3 在本机太慢再换；换模型必须全量重建索引 |
| LLM 服务 | DeepSeek 官方 API（`deepseek-chat`），OpenAI-compatible | 便宜、中文好、接口标准；每次问答只发送问题 + 检索出的白名单切片，不发送整库 |
| LLM 备选 | 阿里云百炼 `qwen-plus`（compatible-mode） | DeepSeek 不可用时切换，代码不用改，只改 `.env` 里的 base_url 和 model |
| Git 敏感历史 | **先立即转私有**，历史清理推迟 | 转私有 1 分钟完成、无破坏性；`git filter-repo` 涉及强制推送，等首版跑通后再单独处理 |
| 面试工具专项资料 | 首版**不**入索引 | 与"待确认"从缓决策一致：先跑通核心闭环，二期再评估 |
| 首版白名单 | 见第二节，共约 30 篇 | 基于 2026-07-10 实际目录扫描结果 |

### 核心表 DDL（Alembic 首个迁移的目标形态）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE documents (
    id BIGSERIAL PRIMARY KEY,
    source_path TEXT UNIQUE NOT NULL,
    title TEXT,
    domain TEXT,
    visibility TEXT DEFAULT 'private',
    status TEXT DEFAULT 'active',
    content_hash TEXT NOT NULL,
    source_modified_at TIMESTAMPTZ,
    indexed_at TIMESTAMPTZ,
    is_active BOOLEAN DEFAULT TRUE
);

CREATE TABLE document_chunks (
    id BIGSERIAL PRIMARY KEY,
    document_id BIGINT REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index INT NOT NULL,
    heading_path TEXT,
    content TEXT NOT NULL,
    token_count INT,
    embedding vector(1024),
    metadata JSONB DEFAULT '{}'
);

CREATE TABLE index_runs (
    id BIGSERIAL PRIMARY KEY,
    started_at TIMESTAMPTZ DEFAULT now(),
    finished_at TIMESTAMPTZ,
    status TEXT,
    discovered_count INT, indexed_count INT, skipped_count INT,
    deleted_count INT, failed_count INT,
    error_summary TEXT
);

-- 切片量 <1万 时全表扫描即可，先不建 ivfflat/hnsw 索引；
-- 等超过 1 万切片再加：
-- CREATE INDEX ON document_chunks USING hnsw (embedding vector_cosine_ops);
```

### 检索 SQL（核心一句）

```sql
SELECT c.content, c.heading_path, d.source_path,
       1 - (c.embedding <=> :query_vec) AS score
FROM document_chunks c
JOIN documents d ON d.id = c.document_id
WHERE d.is_active AND d.status = 'active'
ORDER BY c.embedding <=> :query_vec
LIMIT :top_k;
```

## 四、Prompt 模板（首版直接用）

```text
你是个人软件测试知识助理。严格依据下面的【知识库片段】回答问题。

规则：
1. 只使用片段中的信息，不要补充片段之外的知识。
2. 回答末尾列出用到的来源，格式：[文件路径 > 标题路径]。
3. 如果片段不足以回答，直接回答："知识库中没有找到可靠依据。"

【知识库片段】
{context}

【问题】
{question}
```

拒答走两道闸门：检索分数最高值低于 `SCORE_THRESHOLD` 时不调用 LLM 直接拒答；分数够但内容不相干时靠 Prompt 规则 3 兜底。

## 五、7 个工作日落地排期

每天 2～3 小时的量，对应进度文档的阶段 0～3 + 精简版 5、6：

| 天 | 任务 | 完成标志 |
| --- | --- | --- |
| D1 | GitHub 仓库转私有；创建 `~/Documents/personal-test-rag`；docker-compose 起库；`CREATE EXTENSION vector` 验证 | `psql` 里 `SELECT '[1,2,3]'::vector` 成功 |
| D2 | FastAPI 骨架 + config + `/health`；Alembic 建三张表 | `GET /health` 返回 db 和 pgvector 状态 |
| D3 | loader + cleaner：白名单扫描、frontmatter 解析、Obsidian 链接清洗 | 脚本打印约 30 个文件、正确跳过排除项 |
| D4 | splitter + embedding + indexer：标题切片（300～600 token、重叠 50～80）、bge-m3 批量向量化、按哈希增量写库 | 连跑两次同步，第二次全部 skipped |
| D5 | `/query`：向量检索 + Prompt + DeepSeek 调用 + 引用返回 + 阈值拒答 | 「JMeter 如何用 CSV 参数化」返回正确引用；「今天天气如何」被拒答 |
| D6 | 评测集 30 条（`evals/questions.jsonl`）：每篇主力笔记出 2～3 题 + 5 个应拒答问题；跑 Hit@5 | Hit@5 ≥ 80%，拒答全部命中 |
| D7 | Streamlit 页面：提问、答案、引用、分数、同步按钮 | 从页面完成一次完整问答 |

D6 评测不达标时的调参顺序：先调切片大小 → 再调 top_k → 最后才考虑加关键词检索（那是阶段 4 的事，首版不做）。

## 六、明确不做（防止范围膨胀）

- 混合检索、rerank、Ragas —— 等评测基线出来再说（阶段 4/5）
- Word/PDF/XMind/图片解析 —— 首版只有 `.md`
- LangChain/LlamaIndex 全家桶 —— 首版手写核心链路，代码量不大且全程可控，学习价值更高
- `git filter-repo` 历史清理 —— 转私有后单独排期

## 七、风险与对策

| 风险 | 对策 |
| --- | --- |
| bge-m3 首次下载约 2GB、Mac 上慢 | 先用 `bge-small-zh-v1.5` 跑通链路，最后再换 m3 全量重建对比效果 |
| Python.md 单文件 80KB，切片可能碎 | D4 先单独对它跑切片，人工抽查 5 个切片的 heading_path 和内容完整性 |
| DeepSeek 偶发超时 | openai 客户端设 `timeout=30`、`max_retries=2`；失败返回明确错误不伪造答案 |
| 中文 token 计数不准 | 用模型自带 tokenizer 或按"字符数 ÷ 1.5"估算，不要按空格分词 |
