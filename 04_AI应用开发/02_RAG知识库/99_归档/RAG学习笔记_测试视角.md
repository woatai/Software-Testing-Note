# RAG 学习笔记（测试视角）

## 一、什么是 RAG

RAG（Retrieval-Augmented
Generation，检索增强生成）是一种让大模型结合外部知识库回答问题的技术。

传统大模型：

    用户问题
     ↓
    LLM
     ↓
    答案

RAG：

    用户问题
     ↓
    知识检索
     ↓
    找到相关资料
     ↓
    交给 LLM
     ↓
    生成答案

核心思想：

> 先找到可靠资料，再让大模型基于资料回答。

------------------------------------------------------------------------

# 二、RAG 主链路

RAG 可以拆成两个阶段。

## 阶段一：知识库构建

    Document
     ↓
    Chunk
     ↓
    Embedding
     ↓
    Vector DB

## 1. Document（文档）

来源：

-   PDF
-   Word
-   Markdown
-   网页
-   数据库数据

例如：

    《会员退款规则》

    普通会员退款期限7天。
    VIP会员退款期限15天。
    企业会员退款期限30天。

------------------------------------------------------------------------

## 2. Chunk（文档切片）

为什么需要切片？

因为：

-   文档太长无法直接检索
-   大模型上下文有限
-   需要精准定位知识片段

例如：

原文：

    普通会员退款期限7天。
    VIP会员退款期限15天。
    企业会员退款期限30天。

切成：

    Chunk1：
    普通会员退款期限7天。

    Chunk2：
    VIP会员退款期限15天。

    Chunk3：
    企业会员退款期限30天。

测试关注：

-   是否切断完整语义
-   标题和正文是否分离
-   表格是否被破坏
-   Chunk大小是否合理

------------------------------------------------------------------------

## 3. Embedding（向量化）

Embedding：

> 将文本转换成能够表达语义的一组数字向量。

例如：

    企业会员退款30天

    ↓

    [0.21,0.83,-0.17,...]

注意：

Embedding不是随机分配坐标。

正确理解：

> 根据文本语义生成向量，语义相近的内容在向量空间中通常更接近。

例如：

    会员退款需要多久？

    会员多久可以申请退款？

两个问题文字不同，但语义相近，因此向量距离接近。

------------------------------------------------------------------------

## 4. Vector DB（向量数据库）

作用：

保存：

-   Chunk内容
-   Embedding向量
-   文档信息Metadata

例如：

    Chunk:
    企业会员退款期限30天

    Vector:
    [0.21,0.83,...]

    Metadata:
    来源：《会员规则》
    版本：V2

------------------------------------------------------------------------

# 三、用户查询阶段

用户提问：

    企业会员多久可以退款？

这个叫：

## Query

用户问题也需要 Embedding。

流程：

    Query
     ↓
    Query Embedding
     ↓
    Query Vector

原因：

需要将用户问题转换成向量，然后和知识库中的向量比较相似度。

------------------------------------------------------------------------

# 四、Retrieval（检索召回）

Retrieval：

> 根据用户问题向量，从向量数据库中找到相关Chunk。

流程：

    用户问题向量

    ↓

    Vector DB搜索

    ↓

    找到相似内容

例如：

    企业会员退款期限30天       相似度0.94
    VIP会员退款期限15天        相似度0.86
    普通会员退款期限7天         相似度0.82

Retrieval关注：

> 正确答案有没有被召回。

------------------------------------------------------------------------

# 五、TopK

TopK：

表示取检索结果中排名前K条。

例如：

    TopK=5

代表：

取前5个最相关Chunk。

不是：

-   评分算法
-   模型

只是：

> 取多少条结果。

------------------------------------------------------------------------

# 六、Rerank（重排序）

为什么需要Rerank？

因为第一次检索通常是：

> 快速找到可能相关内容。

但是排序可能不够精准。

所以：

    Retrieval
     ↓
    候选结果
     ↓
    Rerank
     ↓
    重新排序

理解：

    Retrieval = 粗筛

    Rerank = 精排

例如：

第一次：

    Top1 企业会员申请条件
    Top2 VIP退款15天
    Top3 企业会员退款30天

Rerank后：

    Top1 企业会员退款30天
    Top2 VIP退款15天
    Top3 企业会员申请条件

------------------------------------------------------------------------

# 七、Context（上下文）

Rerank之后，选择最相关的Chunk。

这些内容组成：

Context

例如：

    企业会员退款期限30天。
    企业会员退款需要订单号。

然后发送给LLM。

------------------------------------------------------------------------

# 八、LLM生成答案

LLM接收到：

    Context:
    企业会员退款期限30天。

    Question:
    企业会员多久可以退款？

生成：

    企业会员退款期限为30天。

注意：

LLM不是自己去搜索知识库。

流程：

    Retrieval
     ↓
    找到资料
     ↓
    Context
     ↓
    LLM生成答案

------------------------------------------------------------------------

# 九、RAG测试思维

回答错误时，不要只看：

    AI回答错误

应该定位：

    用户问题
     ↓
    Query理解
     ↓
    Embedding
     ↓
    Retrieval
     ↓
    TopK
     ↓
    Rerank
     ↓
    Context
     ↓
    LLM
     ↓
    Answer

------------------------------------------------------------------------

# 十、RAG常见问题定位

## 1. Retrieval问题

表现：

知识库有答案，但是没有找到。

例如：

知识库：

    企业会员退款30天

召回：

    VIP退款15天
    普通退款7天

问题：

检索阶段。

------------------------------------------------------------------------

## 2. LLM生成问题

表现：

已经找到正确资料，但是回答错误。

例如：

Context：

    企业会员退款30天

回答：

    企业会员退款15天

问题：

生成阶段。

------------------------------------------------------------------------

# 十一、测试重点总结

## 数据层

测试：

-   文档是否完整
-   数据是否最新
-   版本是否正确
-   数据冲突处理

------------------------------------------------------------------------

## Chunk层

测试：

-   切片是否合理
-   是否破坏语义
-   表格解析是否正确

------------------------------------------------------------------------

## Embedding层

测试：

-   语义相近是否距离接近
-   模型变化是否影响效果

------------------------------------------------------------------------

## Retrieval层

测试：

-   是否召回正确文档
-   同义词
-   口语化问题
-   错别字
-   长问题

------------------------------------------------------------------------

## Rerank层

测试：

-   正确答案是否排序靠前
-   相似干扰内容影响

------------------------------------------------------------------------

## LLM层

测试：

-   是否幻觉
-   是否根据Context回答
-   是否回答超范围问题

------------------------------------------------------------------------

# 十二、测试人员理解RAG最重要的一句话

> RAG测试不是只测试答案是否正确，而是判断错误发生在哪一个链路环节。

核心链路：

    Document

    Chunk

    Embedding

    Vector DB
     ↓
    Query
     ↓
    Retrieval
     ↓
    TopK
     ↓
    Rerank
     ↓
    Context
     ↓
    LLM
