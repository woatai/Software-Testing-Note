## 公司与产品背景

招聘 JD 原文说明，公司是一家女性成长领域的教育公司，正在自建以下数字化能力：

- 微信小程序：学员端和员工端；
- 企业微信运营链路；
- 内容资源库；
- 分享传播与数据回收；
- 自建业务后台；
- CRM 系统。

团队特点是团队小、迭代快，并采用 AI 协同开发；该岗位需要承担整个产品的质量保障工作。

## 岗位职责

1. 参与产品需求评审，理解业务需求与技术方案，制定测试计划和测试方案，保证测试覆盖全面。
2. 负责客户端测试：微信小程序、H5、APP、企业微信应用的功能、兼容性和真机场景验证。
3. 负责全链路数据测试：验证从内容上传、分享转发到数据回收的完整链路；核对埋点采集、漏斗数据和后台报表准确性，保证“数据回得来、算得对”。
4. 设计并执行测试用例，覆盖功能、边界和异常场景；记录测试结果，保障产品质量。
5. 建设和维护自动化测试，以接口自动化为主，提升回归效率。
6. 负责缺陷记录、跟踪与验证，协助开发定位根因，推动问题闭环。
7. 维护测试计划、测试用例和测试报告等文档，保证过程可追溯、经验可沉淀。

## 任职要求

1. 计算机、软件工程、信息技术等相关专业，或具备同等能力。
2. 熟悉软件测试理论与方法，掌握用例设计，了解软件开发生命周期和质量保证体系。
3. 学习能力强，对 AI 协同开发等新事物有好奇心，能够快速适应。
4. 熟悉至少一种编程语言；熟悉 SQL，能够进行数据核对和对账类测试。
5. 逻辑清晰，善于发现、分析和定位问题。
6. 对质量有责任心，工作严谨细致，同时理解快速迭代中的取舍。
8. 沟通良好，能与产品、开发团队高效协作。

## 根据 JD 构建的待验证系统模型

下面用于理解测试对象，不代表已经确认公司的内部架构、字段和系统完成度。

### 1. 内容与课程链路

`后台创建内容 → 编辑/审核 → 发布 → 学员端展示 → 用户访问 → 更新或下架`

重点风险：发布状态、访问权限、多媒体资源、缓存、多端一致性和下架后的历史链接。

### 2. 学员与员工协作链路

`学员进入系统 → 关联课程/服务 → 员工跟进 → 更新记录或状态 → 后台查询`

重点风险：身份关联、员工数据范围、并发修改、操作记录和敏感信息权限。

### 3. 企业微信与分享传播链路

`内容分享 → 用户点击 → 页面访问 → 事件上报 → 渠道归因 → 后台统计`

重点风险：内容 ID、用户标识、渠道和场景参数、漏报、重复上报、弱网补报和链接失效。

### 4. CRM 客户链路

`用户进入 → 客户建档/关联 → 分配员工 → 跟进 → 标签/状态更新 → 转化统计`

重点风险：重复客户、数据合并、归属、权限、操作审计、状态流转和跨端一致性。

### 5. 数据回收与报表链路

`行为产生 → 埋点上报 → 原始数据存储 → 清洗/去重/聚合 → 报表展示`

重点风险：统计口径、事件唯一性、身份合并、时间边界、数据延迟、筛选条件和 SQL 对账。

## 面试前必须确认

1. 学员端、员工端、CRM、内容后台和数据报表目前哪些已经上线，哪些仍在建设？
2. 测试团队有多少人，该岗位是否是唯一测试或第一位专职测试？
3. 产品、前端、后端、数据和运维分别有多少人，需求与发布节奏如何？
4. 是否有独立测试环境、接口文档、测试账号和可重复构造的数据？
5. 数据回收是实时、准实时还是离线计算，允许的报表延迟是多少？
6. PV、UV、分享、访问、线索和转化的口径由谁定义，是否已有数据字典？
7. 当前接口自动化、CI、日志、监控和缺陷管理分别做到什么程度？
8. 入职前三个月最希望测试岗位优先解决功能稳定性、数据准确性还是回归效率？
